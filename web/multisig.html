Multisig, explained

M-of-N vault · offline · Bitcoin mainnet addresses from public keys only

Offline

What is multisig?

Think of a bank safe-deposit box that needs more than one key. A normal Bitcoin address is 1-of-1: one private key can spend. Multisig means M of N keys must agree before coins can move.

  • N — total keys (cosigners), like N officers who each hold a key.
  • M — how many must sign a payment (e.g. 2-of-3: any two of three).
  • Public key — safe to share for building the vault address (like a lock blueprint).
  • Private key — never paste here; this page refuses WIF / xprv (safety).

What this tool is: an offline calculator that turns M + public keys into a shared receive address and the script that defines the vault.
What it is not: a wallet, a transaction signer, or a blockchain scanner. It will not broadcast anything or “discover” funded combos on explorers (that would hurt privacy).

Policy readout

Set M and N (or generate demo cosigners) — policy text updates after build.

Cosigner checklist

  • ☐ Each cosigner generated their own seed offline / on hardware
  • ☐ Only public keys (or xpubs) are shared to build the vault
  • ☐ M and N written down for recovery (e.g. 2-of-3)
  • ☐ BIP67 sort agreed (recommended) so everyone builds the same address
  • ☐ Backup plan: who holds which key; how to replace a lost cosigner
  • ☐ No private keys or seeds pasted into this page

Where do the public keys come from?

A multisig vault is built from several people’s public keys (N cosigners). You do not paste recovery phrases into the builder — only the compressed public key of each cosigner (66 hex characters, starts with 02 or 03).

  • Real life: each person generates their own seed in a hardware wallet / Sparrow / Coldcard, then exports the public key (or xpub) for the multisig setup. Private keys never leave their device.
  • In this lab: use Generate demo cosigners below to create N throwaway seeds offline and fill their public keys automatically — so you can learn without hardware.
  • Or paste public keys you already have (hex), one per line.

Demo seeds are for education only. The BIP39 Lab page is where you explore a single seed’s addresses; multisig is about combining several public keys into one shared address.

1 · Generate demo cosigners (optional)

This demo uses BIP84 native segwit only (purpose 84') — not BIP44/BIP86. For each cosigner you get: BIP39 words, entropy bits, BIP84 zpub (account m/84'/0'/0' — the SLIP-132 form of the BIP84 account public key people call “xpub” in casual speech, but the prefix is zpub), plus the compressed pubkey at m/84'/0'/0'/0/0 used to build the simple M-of-N script in step 2.

N people in the vault. Example: N=3 → often M=2 (2-of-3).

BIP39 word count for every demo cosigner
